5.2 · Петля самокоррекции: агент чинит, машина решает

🎯 С кодом (Python) · ✅ Интерактивный квиз · ⏱️ ~15 минут

🎯 Зачем это бизнесу

Представьте: вечером вы ставите агенту задачу «приведи этот пакет документов в порядок», утром заходите — либо результат проверен и принят, либо на столе аккуратная эскалация: «пробовал вот это, не вышло, вот состояние, продолжайте». Без ночных дежурств и без сюрпризов вроде «агент всю ночь менял цифры в таблице, и теперь там хуже, чем было».

Это инженерная петля: не «агент сделал и сказал готово» (урок 0.1 как раз про этот разрыв), а цикл проверить → исправить → проверить снова, где решение «готово» принимает не модель, а машина.

📚 Что изучаем

Анатомия петли

for attempt in 1..MAX:
    done, evidence = verify()          # 1. ПРОВЕРИТЬ: тесты + линт
    if done: return SUCCESS            #    решение принимает машина
    fp = fingerprint(evidence)         # 2. отпечаток падения (хэш
    if fp == last_fp:                  #    строк FAILED)
        stall += 1                     # 3. буксование: тот же отпечаток
    if stall >= LIMIT: return ESCALATE #    -> человек
    patch = generate(lessons)          # 4. модель пишет минимальный фикс
    apply(patch)                       # 5. применить (через харнесс 5.1!)
    lessons.append(summarize(evidence))# 6. провал -> одна строка-урок

Пять узлов, которые делают петлю надёжной

УзелПроблема без него
Верификатор — код, не модельМодель скажет «вроде починил» на словах; pytest + ruff — по exit-кодам
Отпечаток паденияАгент трижды «чинит» одно и то же, меняя несущественное — петла крутится вхолостую
Уроки из проваловПопытка №4 повторяет ошибку попытки №1 — каждый провал сжимается в одну строку «пробовал X — не вышло, потому что Y» и подмешивается дальше
Эскалация с состояниемПетла обязана уметь проигрывать: файл с целью, причиной и уроками — человек продолжает с места обрыва
Дистилляция опытаПобедная траектория выбрасывается — в следующий раз агент снова идёт 9 попыток вместо 1

Отпечаток падения — детектор вращения вхолостую

Главный враг петли — не падение, а одно и то же падение. Отпечаток — короткий хэш от строк с «FAILED» и «Error» из вывода проверки. Хэш не изменился между попытками — значит, агент не продвинулся, даже если его правки выглядят по-разному. Два одинаковых отпечатка подряд — стоп, эскалация. Это прямое продолжение урока 3.1: буксование на одном симптоме — сигнал подниматься на слой выше, а не долбить ту же стену.

Опыт — актив: платишь за урок один раз

Если задача потребовала четырёх попыток, система, которая выбрасывает сессию, оплатила этот опыт один раз. Петля сжимает победную траекторию в компактный разобранный пример («цель → ключевые решения → проверенный исход», без содержимого файлов и секретов) и складывает в библиотеку опыта. Следующий запуск похожей задачи начинает контекст с этого примера — и решает с первой попытки. Девятая попытка прошлого раза становится первой попыткой следующего.

Границы петли. MAX попыток фиксирован и мал (3–4) — петла не бесконечна. Эскалация — нормальный исход, а не провал системы: цель петли не «решить любой ценой», а «не отдать человеку мусор». Всё, что петля трогала, — под харнессом из урока 5.1: с откатом и журналом.

🛠️ Как применить

🛒 Закупки: привести реестр цен к формату

Верификатор — скрипт: все колонки на месте, валюта ISO-кодом, дата в формате ДД.ММ.ГГГГ, цена — число. Агент правит строки, пока скрипт не пройдёт; не прошло за 4 попытки — файл состояния: «строки 12 и 47, вот что пробовал». Утром вы тратите две минуты вместо часа разбора.

📊 Финансист: сверка выгрузки

Цель «суммы сходятся с выпиской». Верификатор считает расхождение по строкам. Уроки из провалов («пробовал округлять копейки — не тот слой, расхождение в дубле строки») не дают повторить путь в никуда.

🧑‍💼 HR: пакет документов кандидата

Проверка — чек-лист обязательных полей и форматов. Петля доводит до полного комплекта или эскалирует с точным списком недостающего. Опыт «какой порядок заполнения быстрее» копится между кандидатами.

✅ Чеклист принятия результата

  • Условие «готово» — машинная проверка (exit-коды), а не слова модели
  • Каждый провал сжат в одну строку-урок и передаётся следующей попытке
  • Одинаковый отпечаток падения N раз подряд → эскалация, а не новая попытка
  • Эскалация сохраняет возобновляемое состояние: цель, причина, уроки
  • Победная траектория дистиллирована в пример без данных сессии и сохранена
  • Число попыток ограничено; всё выполнение под харнессом с откатом

A) Модель, когда уверена в ответе

A) Чтобы красиво логировать ошибки
B) Чтобы детектировать буксование: тот же отпечаток подряд = агент не продвигается = пора эскалировать человеку
C) Чтобы штрафовать модель за ошибки

Вопрос 3: Что такое дистилляция опыта и зачем она?

A) Сохранение полной переписки с моделью для архива
B) Сжатие победной траектории в пример без данных сессии, чтобы похожие задачи решались с первой попытки
C) Обучение собственной нейросети на логах

🎯 Главное из урока

Надёжная петля = машинный вердикт + детекция буксования + уроки из провалов + умение проиграть. Модель внутри петли — генератор гипотез, а не судья. Судья — код. А опыт, купленный дорогими попытками, превращается в актив, который платит дивиденды на каждой следующей задаче.
