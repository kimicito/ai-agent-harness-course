4.1 · Роли: планировщик → исполнитель → проверяющий

🎯 Без кода · ✅ Интерактивный квиз · ⏱️ ~12 минут

🎯 Зачем это бизнесу

Уровень 2 дал правило «один агент — одна задача». Но что, если одна задача большая: разбор тендера, запуск кампании, подготовка годового отчёта? Делать всё одним агентом — значит, что он сам ставит себе цели, сам исполняет, сам хвалит себя за результат.

Студент не проверяет собственную контрольную. Тот, кто писал текст, уже убедил себя в его правильности — помните эффект адвоката из урока 0.2. Поэтому большие задачи делятся между ролями — как у оркестра: дирижёр не играет на скрипке, скрипач не оценивает партию трубы.

📚 Что изучаем

Три роли вместо одного «сделай всё»

РольЧто делаетЧего НЕ делает
🧭 ПланировщикРазбивает большую задачу на шаги, определяет порядок, заводит постусловияНе выполняет шаги сам
🔨 ИсполнительДелает один шаг за раз, сдаёт по постусловиюНе решает, что делать дальше, и не оценивает свой результат
🔍 ПроверяющийПринимает шаг по чек-листу и постусловию; пишет замечанияНе переписывает работу заново — возвращает на доработку

Роли могут жить в одном агенте — как костюмы в гардеробной: сменил роль, сменил инструкцию. А могут — в разных агентах или разных сессиях. Принципиально важно одно: проверяющий не видит рассуждений исполнителя. Иначе он унаследует их уверенность.

Как это устроено без программирования

Шаг 1. Планировщик пишет план в ПРОГРЕСС.md:
       шаги, у каждого — постусловие (урок 2.2)
Шаг 2. Исполнитель берёт ОДИН шаг (урок 2.4),
       делает, сдаёт результат + отметки по постусловию
Шаг 3. Проверяющий смотрит результат в чистой сессии:
       по чек-листу, выборочная сверка (урок 0.3).
       Принял → запись в ПРОГРЕСС.md → следующий шаг.
       Не принял → замечание в формате
       «что / почему / что делать» (урок 3.3)
Шаг 4. Контрольная точка между шагами,
       меняющими файлы (урок 1.4)

Разделение ролей — главный антидот против разрыва

В курсе упряжи есть измеримая величина — верификационный разрыв: сколько раз агент заявил «готово», а независимая проверка нашла ошибку. У команд без разделения ролей он составляет заметную долю всех задач. Разделение «исполнил ≠ проверял» схлопывает разрыв, потому что проверяющий не заинтересован в красивом результате — только в соответствии чек-листу.

Две ловушки. (1) Проверяющий слишком снисходителен — «и так сойдёт». Лечение: у проверяющего есть только два вердикта — «принято» или «возвращено с замечанием», без третьего. (2) Ролей стало больше трёх-четырёх — планировщик, исполнитель, проверяющий и пара специалистов. Дальше — бюрократия: каждая передача роли стоит времени. Начинайте с трёх.

🛠️ Как применить

🛒 Закупщик: разбор тендера

Планировщик: список документов и сроки. Исполнитель: заполняет по одной форме. Проверяющий: сверяет каждую форму с требованиями закупки. Сдавали «пакетом» и ловили замечания комиссии — сдаёте по формам, замечаний в разы меньше.

📢 PR: кампания из шести текстов

Планировщик — контент-план с постусловиями на каждый текст. Исполнитель пишет по одному тексту. Проверяющий (свежая сессия) — по бренд-чек-листу: тон, обещания, цифры. Текст, который «сам себя проверял», выглядел гладко и содержал три фактические ошибки.

📊 Финансист: годовой отчёт

Разделы — шагами. Исполнитель считает раздел, проверяющий сверяет с выгрузками. Главное правило уровня 0 в действии: отчёт, который никто не сверил, — это рассказ про цифры.

✅ Чеклист принятия результата

  • Большие задачи разбиты на шаги с постусловиями в ПРОГРЕСС.md
  • Проверяющий работает в чистой сессии и не видит рассуждений исполнителя
  • У проверяющего два вердикта: «принято» или «возвращено с замечанием»
  • Ролей не больше четырёх — больше это уже бюрократия

📝 Проверка понимания

Вопрос 1: Почему исполнитель не должен проверять свой результат?

A) Он недостаточно опытный для проверки
B) Он уже убедил себя в правильности — эффект адвоката; проверка будет нечестной
C) Чтобы занять ещё одного агента

Вопрос 2: Какое главное условие для роли проверяющего?

A) Он старше по опыту, чем исполнитель
B) Чистая сессия, чужой результат, чек-лист; рассуждений автора не видит
C) Он должен переписать результат заново, если не понравился

Вопрос 3: Что такое верификационный разрыв?

A) Разница между плановым и фактическим временем задачи
B) Доля случаев, когда агент заявил «готово», а независимая проверка нашла ошибку
C) Расстояние между двумя нейросетями

🎯 Главное из урока

Большую задачу играет оркестр, а не солист. Планировщик ставит шаги, исполнитель делает по одному, проверяющий принимает в чистой сессии по чек-листу. Разделение «писал ≠ проверял» — главный способ схлопнуть верификационный разрыв, который иначе съедает треть ваших результатов.
